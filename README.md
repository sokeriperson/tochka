## 1. Как всё устроено

Сайт — набор статических файлов. Логика бэкенда распределена между несколькими сервисами:

| Задача | Где решается |
|---|---|
| Отдача HTML / CSS / JS | Beget (`public_html`) |
| Рилсы, галерея, меню (редактируются владельцем) | Firebase Firestore |
| Вход в админку | Firebase Authentication (email + пароль) |
| Хранение видео и фото | Cloudflare R2 |
| Загрузка файлов из админки в R2 | Cloudflare Worker `tochka-r2-upload` |
| Уведомление о брони в Telegram | PHP `send-lead.php` на Beget |
| Письма с откликами на вакансии | PHP `send-lead.php` (SMTP Beget) |
| Копия всех заявок | Firestore, коллекция `bookings` |
| Карта | Yandex Maps JS API 2.1 |
| Шрифты | Google Fonts (Oswald, Inter, Murecho) + локальные `Furore.otf`, `mr_daray_daray.otf` |

### Поток данных

```
Посетитель ──► Beget: HTML/CSS/JS
                  │
                  ├─ чтение рилсов / галереи / меню ──► Firestore (reels, gallery, menu)
                  │        └─ ссылки на медиа ──────────► Cloudflare R2 (pub-….r2.dev)
                  │
                  └─ заявка (бронь / вакансия) ─┬─► Beget: send-lead.php ─► Telegram (бронь)
                                                │                          └► SMTP-письмо (вакансия)
                                                └─► Firestore: bookings (резервная копия)

Владелец ──► /admin.html ──► Firebase Auth ──► правка Firestore
                          └─► Worker tochka-r2-upload ──► R2 (загрузка файлов)
```

Заявка считается доставленной, если сработал **хотя бы один** из двух путей (PHP или Firestore) — см. `public_html/leads.js`.

## 4. Firebase

Проект Firebase: **`tochka-a1f4f`** (Project ID). Настройки подключения — в `public_html/firebase-config.js`. SDK подключается напрямую с CDN `gstatic.com` (версия 12.15.0), установка через npm не нужна.

### 4.1 Используемые сервисы

| Сервис | Где используется |
|---|---|
| **Firestore** | рилсы, галерея, меню, заявки |
| **Authentication** (email/пароль) | только вход в админку (`admin.js`) |
| **Analytics** | подключается автоматически, если браузер поддерживает |
| Cloud Storage | импортируется в конфиге, но **не используется** (файлы лежат в R2) |
| Hosting | сейчас сайт на Beget; Firebase Hosting — резервная копия на `*.web.app` |

### 4.2 Коллекции Firestore

**`reels`** — видео-карусель на главной (читают `reels-loader.js`, `admin.js`)

| Поле | Тип | Описание |
|---|---|---|
| `videoUrl` | string | ссылка на видео в R2 |
| `posterUrl` | string | ссылка на обложку (если нет — админка делает кадр из видео) |
| `videoPath` | string | путь файла в R2 |
| `linkUrl` | string | куда ведёт клик по рилсу (необязательно) |
| `previewSeconds` | number | длительность превью при наведении, 1–30 |
| `order` | number | порядок показа (по возрастанию) |
| `active` | boolean | показывать ли на сайте |
| `createdAt` | timestamp | серверное время создания |

**`gallery`** — фото для страницы галереи

| Поле | Тип | Описание |
|---|---|---|
| `imageUrl` | string | ссылка на изображение в R2 |
| `imagePath` | string | путь файла в R2 |
| `order` | number | порядок |
| `createdAt` | timestamp | время создания |

**`menu`** — разделы меню

| Поле | Тип | Описание |
|---|---|---|
| `label` | string | название раздела |
| `unit` | string | общий объём/единица (например «мл»), необязательно |
| `items` | array | позиции меню (формат ввода в админке: `Название \| Original name \| объём \| цена`) |
| `image`, `imagePath` | string | первая картинка раздела и её путь в R2 |
| `image2`, `imagePath2` | string | вторая картинка (необязательно) |
| `order` | number | порядок |
| `createdAt` | timestamp | время создания |

**`bookings`** — все заявки (брони и отклики на вакансии), пишет `leads.js`

| Поле | Тип | Описание |
|---|---|---|
| `type` | string | `booking` или `vacancy` |
| `source` | string | откуда заявка (заголовок страницы / кнопка) |
| `name`, `phone`, `contact`, `comment` | string | данные формы |
| `page` | string | путь страницы, с которой отправлено |
| `createdAtClient` | string | время по часам клиента (ISO) |
| `createdAt` | timestamp | серверное время |

В админке заявки делятся на «Брони» (`type = booking`) и «Отклики на вакансии» (`type = vacancy`).

### 4.3 Правила безопасности (Firestore Rules)

Файла `firestore.rules` в репозитории нет — **проверьте и зафиксируйте актуальные правила из консоли Firebase**. В `bookings` лежат имена и телефоны посетителей, поэтому правила критичны. Рекомендуемая схема:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Публичный контент: читают все, пишет только вошедший админ
    match /{coll}/{doc} {
      allow read:  if coll in ['reels', 'gallery', 'menu'];
      allow write: if coll in ['reels', 'gallery', 'menu'] && request.auth != null;
    }

    // Заявки: создавать может любой посетитель, читать/удалять — только админ
    match /bookings/{doc} {
      allow create: if true;
      allow read, update, delete: if request.auth != null;
    }
  }
}
```

Пользователей Authentication должно быть ровно столько, сколько людей, которым нужен доступ в админку (регистрация новых пользователей из публичного интерфейса не предусмотрена — создавайте их в консоли Firebase → Authentication → Users).

> Правила нужно хранить в локальном файле `firestore.rules` и выкатывать через `firebase deploy --only firestore:rules`. Правки только в консоли будут перезаписаны при следующем деплое из CLI.

## 5. Cloudflare (R2 и Workers)

### 5.1 R2 — хранилище медиа

- Бакет: `tochka` (аккаунт `korolev-tt`).
- Публичный адрес: `https://pub-b12e5d4cbca74818b8e641984333f707.r2.dev` (используется в `<link rel="preconnect">` в `index.html`; конкретные ссылки на файлы лежат в Firestore).
- В Firestore хранятся только **ссылки**; сами файлы — в R2. Исходящий трафик R2 не тарифицируется — поэтому видео размещены именно там.
- **CORS бакета** должен разрешать `GET`/`HEAD` с домена сайта и содержать:
  - `AllowedHeaders`: `["Range"]`
  - `ExposeHeaders`: `["Content-Range", "Content-Length", "Accept-Ranges"]`

  Без этого не работает перемотка/потоковое видео, а `canvas.toBlob` в админке (генерация обложки из кадра видео) падает с ошибкой «tainted canvas».

### 5.2 Worker `tochka-r2-upload` — загрузка файлов

URL: `https://tochka-r2-upload.korolev-tt.workers.dev` (константа `R2_WORKER_URL` в `admin.js`).

Контракт (по клиентскому коду):
- Запрос: `POST`, `multipart/form-data`, поле `file`; заголовок `Authorization: Bearer <UPLOAD_TOKEN>`.
- Ответ: JSON `{ "url": "<публичная ссылка>", "path": "<ключ в бакете>" }`.
- Секрет `UPLOAD_TOKEN` хранится в настройках Worker (Settings → Variables and Secrets).

### 5.3 Worker `tochka-telegram-proxy` — прокси к Telegram

URL: `https://tochka-telegram-proxy.korolev-tt.workers.dev` (`telegram-notify.js`). Принимает JSON `{type, source, name, phone, contact, comment, page}`, токен бота хранится в Secrets (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). В актуальной схеме заявки идут через `send-lead.php`, поэтому этот Worker, вероятно, не задействован (см. п. 13).

### 5.4 Где лежит код Workers

Исходники Workers **в репозитории отсутствуют** — они редактируются в панели Cloudflare (Workers & Pages → нужный Worker → Edit code)

## 6. PHP-скрипты на Beget

### `send-lead.php`
Принимает `POST` с JSON от `leads.js` по адресу `https://tochka-club.ru/send-lead.php`.

- `type = booking` → сообщение в Telegram-группу (Bot API `sendMessage`, через cURL).
- `type = vacancy` → письмо по SMTP (`smtp.beget.com:465`, отправитель `noreply@tochka-club.ru`) на адреса из `$recipients`.
- Проверка CORS по списку `$allowedOrigins` (домен сайта, `*.web.app`, `*.firebaseapp.com`, `localhost:63342` для разработки). **Добавляйте сюда новый домен, если сайт переезжает.**
- Ответ: JSON `{ ok: true/false, results: {...} }`; при полной неудаче — HTTP 502.

### `send-vacancy-email.php`
Прежний скрипт отправки откликов по SMTP. Актуальная схема использует `send-lead.php`; файл оставлен для совместимости (см. п. 13).

### Настройка секретов (обязательно после развёртывания)

В репозитории вместо реальных значений стоят заглушки. На сервере в `send-lead.php` должны быть реальные значения:

| Переменная | Что подставить |
|---|---|
| `$TG_TOKEN` | токен Telegram-бота (BotFather) |
| `$TG_CHAT_ID` | ID чата/группы, куда бот пишет брони |
| `$smtpUser` / `$smtpPass` | почтовый ящик Beget и его пароль |
| `$recipients` | адреса, на которые приходят отклики на вакансии |

### Ограничение: PHP 5.6
На хостинге работает **PHP 5.6.40**. Нельзя использовать синтаксис PHP 7+: `??`, `??=`, стрелочные функции, `catch (Throwable $e)`, скалярные тайп-хинты. Результат — тихая ошибка парсинга и пустой ответ HTTP 500. Вместо `??` применяйте `isset($x) ? $x : $default`. Если есть возможность, переключите версию PHP в панели Beget на актуальную и проверьте скрипты.

## 7. Админ-панель

Адрес: `/admin.html`. Вход — email и пароль пользователя Firebase Authentication.

| Раздел | Что можно делать |
|---|---|
| **Рилсы** | загрузить видео (до 50–70 МБ), обложку (если не задана — генерируется из первого кадра), ссылку, длительность превью; менять порядок, включать/выключать, удалять; кнопка «сгенерировать недостающие обложки» |
| **Галерея** | загрузить несколько фото сразу, менять порядок, удалять |
| **Меню** | создать раздел, задать объём, добавить 1–2 картинки, редактировать позиции (`Название \| Original name \| объём \| цена`) |
| **Заявки** | таблица броней и откликов на вакансии, удаление обработанных |

Советы:
- Видео сжимайте заранее (≤ 10-15 МБ), вертикальный формат для рилсов.
- Для меню используйте картинки одинаковых пропорций — иначе блок `content__img` отображается с разным размером (исправляется нормализацией холста при подготовке картинки).
- Изменения рилсов и галереи появляются на сайте сразу (подписка `onSnapshot`).

## 8. Локальный запуск

Сборки нет, но скрипты подключаются как ES-модули (`type="module"`), поэтому файл нельзя открыть двойным кликом (`file://`) — нужен любой локальный HTTP-сервер:

```bash
cd public_html
python3 -m http.server 8000
# открыть http://localhost:8000
```

Либо встроенный сервер WebStorm (порт 63342 уже разрешён в CORS `send-lead.php`).

Что работает локально: вёрстка, чтение Firestore и R2 (публичное чтение), вход в админку. Что может не работать: отправка на `send-lead.php` — CORS разрешает только перечисленные в нём origin'ы; при локальном запуске на другом порту добавьте его в `$allowedOrigins` на тестовом окружении. Добавьте `?debug` к URL страницы, чтобы после отправки формы показалась отладочная панель с результатом каждого канала доставки.

Проверка кэша при тестировании: открывайте в режиме инкогнито или добавляйте `?v=N` к адресу страницы/файла.

## 9. Бесплатные лимиты сервисов

Актуально на 1 октября 2026, проверяйте на официальных страницах — условия меняются.

**Firebase, тариф Spark (бесплатный)**

| Что | Лимит |
|---|---|
| Firestore: хранение | 1 GiB |
| Firestore: чтения | 50 000 в сутки |
| Firestore: записи | 20 000 в сутки |
| Firestore: удаления | 20 000 в сутки |
| Firestore: исходящий трафик | 10 GiB в месяц |
| Authentication | 50 000 активных пользователей в месяц |
| Hosting | 10 GB хранилища, 360 МБ трафика в сутки |
| Cloud Storage, Cloud Functions | недоступны на Spark |

**Cloudflare**

| Что | Лимит |
|---|---|
| Workers Free: запросов | 100 000 в сутки |
| Workers Free: CPU на запрос | 10 мс |
| R2: хранение | 10 GB |
| R2: операции записи (Class A) | 1 млн в месяц |
| R2: операции чтения (Class B) | 10 млн в месяц |
| R2: исходящий трафик | бесплатно |

Сверх бесплатного R2 стоит $0,015 за GB в месяц, $4,50 за млн записей и $0,36 за млн чтений.

**Что может упереться первым.** Каждая загрузка страницы читает все документы коллекций `reels`, `gallery` и `menu`. При 20–40 документах суммарно бесплатных 50 000 чтений в сутки хватает примерно на 1 200–2 500 посетителей в день (оценка). При росте трафика — кэшировать списки в `localStorage`/`sessionStorage` или перейти на тариф Blaze.

### Технические заметки по вёрстке (чтобы не наступать на грабли)

- `overflow-x: hidden` ставить только на `html`, не на `html` и `body` одновременно (иначе у `body` появляется внутренний скролл).
- `backdrop-filter: blur()` и `filter: blur()` на больших декоративных блоках сильно роняют FPS на iOS Safari — вместо них используются многоступенчатые `radial-gradient()`.
- Мобильные стили — только внутри `@media (max-width: 900px)`, десктопные добавки — внутри `@media (min-width: 901px)`; голые глобальные правила «протекают» в оба режима.
- Модификатор `.modal.policy-modal` (две классовые специфичности) используется, чтобы не затронуть стили модального окна брони.
- В CSS-градиентах бывают невидимые символы (неразрывные пробелы) после копирования — если градиент не применяется, перепечатайте значение вручную.
- Firebase Hosting кэширует агрессивно: для `index.html` настроить `Cache-Control: no-cache` в `firebase.json`; при тестах использовать инкогнито или `?v=N`.
